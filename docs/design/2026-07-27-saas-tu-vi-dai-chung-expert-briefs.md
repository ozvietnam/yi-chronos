## 0. TL;DR gửi expert

YI không phải app bói. User nhập ngày giờ sinh → thấy **cấu trúc tâm** trên lá Tử Vi → nhận **1 việc nhỏ tuần này** → mục tiêu = **bớt dính mắc**, không “đoán trúng”.

Anh cần 4 chuyên gia, mỗi người **1 buổi 90 phút** + 1 trang ghi chú. Không retainer trong vòng này.

## 2. Bốn brief riêng (copy gửi từng người)

### Expert #1 — Product / UX đại chúng

**Profile:** PM hoặc UX lead app VN (edtech / health / fintech consumer).  
**Không cần** biết Tử Vi.

**Chuẩn bị:** Mở site như user mới (mobile + desktop). Không đọc docs kỹ thuật.

**90 phút:**
1. Onboarding → lập lá (0–20’)  
2. Đọc kết quả lần đầu: 60 giây nói to “tôi hiểu gì?” (20–40’)  
3. Tìm “việc nhỏ tuần này” — có / không / bao lâu (40–60’)  
4. So với 1 app quen (Calm / journaling / health) — gap (60–80’)  
5. Đề xuất funnel 5 bước tối đa (80–90’)

**Câu hỏi bắt buộc:**
- User đại chúng có cần thấy đủ 12 cung ngay không?
- Jargon nào phải đổi (cung, chính tinh, miếu/hãm, Đại Vận…)?
- CTA sau buổi đọc là gì?

**Deliverable:** Funnel đề xuất + “cắt / giữ / ẩn sau fold” cho UI hiện tại.

---

### Expert #2 — Tử Vi thực hành (lineage)

**Profile:** Thầy có học trò, đọc được Trần Đoàn / phái rõ; tránh chỉ content TikTok.  
**Biết** an sao + luận Mệnh–Thân–Đại Vận cơ bản.

**Chuẩn bị:** 2 case Anh gửi trước (ngày giờ + giới tính). Tự lập bằng tay hoặc phần mềm quen, rồi đối chiếu YI.

**90 phút:**
1. Đối chiếu an sao / cung Mệnh / cục (0–30’)  
2. Nghe tone output Quán chiếu — có phải “bói” không? (30–50’)  
3. Chỗ nào **đúng sách** nhưng **không nên đưa đại chúng** (50–70’)  
4. 3 lỗi nặng nếu ship sớm (sai giờ, thiếu true solar, trộn phái…) (70–90’)

**Câu hỏi bắt buộc:**
- Engine có lệch phái nào so với cách thầy dạy?
- Giờ không rõ / Tý đầu–cuối: YI xử lý thế nào mới trung thực với đại chúng?
- Đại Vận trên UI: hiện bao nhiêu là đủ cho người mới?

**Deliverable:** Pass / Fail an sao + danh sách “không ship đại chúng” + 3 fix ưu tiên.

### Expert #3 — Phật học / đạo đức nội dung

**Profile:** Học giả Nikāya hoặc tăng/ni / editor sách Phật VN; không cần biết Tử Vi sâu.

**Chuẩn bị:** Đọc GOAL-THU-THU + 8–10 đoạn output mẫu (Quán chiếu + disclaimer).

**90 phút:**
1. “Mượn khung soi tâm” — có chiếm dụng / xuyên tạc không? (0–25’)  
2. Rà 10 output: sợ hãi / định mệnh / tà mạng (Brahmajāla) (25–55’)  
3. Disclaimer + Ngũ Uẩn trên UI — giữ / sửa câu chữ (55–75’)  
4. Red lines API phải chặn (75–90’)

**Câu hỏi bắt buộc:**
- Có được gắn Bát Chánh Đạo vào lá số công khai không? Điều kiện gì?
- Câu nào trong mẫu đang “đóng số phận”?
- Survey 1 câu đo “thấy đúng tâm” vs “đoán vận” — wording nào trung thực?

**Deliverable:** Checklist đạo đức + disclaimer bắt buộc (≤120 chữ) + list câu cấm.

---

### Expert #4 — Legal PDPL / privacy VN

**Profile:** Luật sư dữ liệu cá nhân VN (PDPL 2026); biết cross-border / LLM là lợi thế.

**Chuẩn bị:** 1 trang kiến trúc: ngày giờ sinh, lá số, chat/LLM, lưu VPS, Firebase auth (nếu có).

**90 phút:**
1. Phân loại dữ liệu nhạy (sinh, suy luận tính cách) (0–20’)  
2. Consent flow đại chúng (20–45’)  
3. Lưu VN vs gọi LLM nước ngoài (45–70’)  
4. Retention / xóa tài khoản / breach 72h (70–90’)

**Câu hỏi bắt buộc:**
- MVP được go-live với SQLite/VPS hiện tại không, hay bắt buộc Postgres+VN trước?
- Text consent tối thiểu trên màn nhập ngày sinh?
- Chatbot lá số (tương lai) đổi gì về pháp lý?

**Deliverable:** Gap list P0/P1 + mẫu câu consent (tiếng Việt).

## 3. MVP 90 ngày — Gương Tử Vi đại chúng

### Value proposition (1 câu)
«Nhập ngày giờ sinh → thấy tâm đang chạy trên lá Tử Vi → chọn 1 việc nhỏ tuần này.»

### Màn hình sau login (một composition)

| Khối | Nội dung | Nguồn kỹ thuật gần |
|---|---|---|
| A. Hero | Tên · tuổi · Cục · cung Mệnh (sao chính) | `castTuViLaSo` |
| B. Đọc | 3–5 câu plain: khí Mệnh đang phản chiếu gì | Quán chiếu / chân dung rút gọn (không 8 lớp đầy đủ ngay) |
| C. Chỗ lệch | 1 GAP (vd. khí hãm / Thân lệch Mệnh / Đại Vận đang…) | deep / ngu_uan gap |
| D. Việc nhỏ | 1 action tuần này (có checkbox + lịch sử 4 tuần) | practice từ lớp khe tỉnh thức |
| E. Disclaimer | Cố định footer | Expert #3 chốt wording |
| F. Đi sâu | Fold: 12 cung · ĐV · PDF — không mở sẵn | `TuViLaSoPanel` hiện tại |

**Default ẩn với đại chúng:** Lexicon, Research, Hermes đa sage, Pytago, Kỳ Môn, so sánh phái, jargon Decoz/Cheiro.

**Pytago:** tab “Số học” sau khi user hoàn thành ≥1 buổi Tử Vi — hoặc owner-only đến khi Tử Vi funnel ổn.

### Metrics (north-star)
1. % hoàn thành buổi đọc đầu (tới checkbox việc nhỏ)  
2. % quay lại tuần 2  
3. Survey 1 câu: “thấy đúng tâm” / “muốn đoán vận” / “không hiểu”  
4. 0 output vi phạm red-line đạo đức / 0 PII incident  

### Lộ trình kỹ thuật gợi ý (bám expert)

| Tuần | Việc |
|---|---|
| 1–2 | Gặp 4 expert · tổng hợp 1 PRD |
| 3–5 | UI “1 buổi đọc” (wrapper trên cast Tử Vi) · cắt jargon · việc nhỏ + streak |
| 6–7 | Disclaimer + API guardrails (#3) · consent (#4) |
| 8–10 | Chất lượng: 1–2 chính tinh / Mệnh plain đạt mẫu thủ thư (8 lớp rút còn 3 câu user) |
| 11–12 | Soft launch waitlist VN · đo metric · quyết retainer Product + thầy TV |

### Không làm trong 90 ngày
- Thêm môn mới làm default  
- Hợp nhất Tử Vi + Pytago thành một lời  
- Council đa sage thô cho user mới  
- Retainer 3 tháng trước soft launch
